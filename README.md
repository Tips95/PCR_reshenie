# Правовой центр «Решение» — лендинг

Одностраничный сайт юридической компании (банкротство физических лиц, Грозный).
Продакшен: [pcr-reshenie.ru](https://pcr-reshenie.ru)

## Технологии

- **Next.js 14** (App Router, статический экспорт `output: 'export'`)
- **TypeScript**, **React 18**
- **Tailwind CSS**
- **Framer Motion** — анимации
- **Яндекс.Формы** — приём заявок, **Яндекс.Метрика** — аналитика

## Запуск

```bash
npm install
npm run dev          # разработка, http://localhost:3000
npm run build        # продакшен-сборка в каталог out/
npm run optimize:images  # пересжатие картинок и генерация og-image.jpg
```

Сборка статическая: после `npm run build` каталог `out/` заливается на хостинг
как есть. `npm start` (`next start`) при таком режиме не используется.

Локально проверить собранную версию: `npx serve out`.

## SEO

Контакты и адрес правятся **только** в `src/lib/site.ts` — оттуда они попадают в
шапку, футер, контакты, микроразметку и юридические страницы.

Что настроено:

- canonical, Open Graph и Twitter-карточка, превью `public/og-image.jpg`
- микроразметка `LegalService`, `WebSite` (в `layout.tsx`) и `FAQPage` (в `FAQ.tsx`)
- `public/robots.txt` и `public/sitemap.xml` — при добавлении новых страниц
  sitemap нужно обновлять вручную
- `trailingSlash: true`, поэтому внутренние адреса пишутся со слэшем: `/privacy/`

## Изображения

Оригиналы фотографий лежат в `source-images/` (вне сборки). Скрипт
`npm run optimize:images` сжимает их в WebP 400×400 в `public/assets/lawyers/`,
ужимает логотип и собирает Open Graph превью. Тяжёлые исходники в `public/`
класть не нужно — они целиком попадают в статику.

## Аналитика и формы

- Яндекс.Метрика (счётчик `103640261`) подключена в `layout.tsx` через
  `next/script` со стратегией `afterInteractive`.
- Форма заявки — встроенная Яндекс.Форма в `Contact.tsx`. Заявки приходят в
  интерфейс Яндекс.Форм, серверный код для отправки не используется.
